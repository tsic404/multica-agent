# 任务拆分与验收标准指南

## ⚠️ 拆分必要性检查（最优先 — 拆之前必读）

任务拆分不是机械操作。**在拆任何 Epic 之前，先判断是否需要拆。**

| 检查项 | 条件 | 结论 |
|--------|------|------|
| 复杂度 | 需要 >1 人或 >4 小时专注工作 | 可以拆 |
| 复杂度 | 一个人 ≤4 小时能完成 | **不拆** — Epic 本身就是任务 |
| 独立性 | 能识别 ≥2 个真正独立、有各自验收标准的交付物 | 可以拆 |
| 1:1 映射 | 拆分后只有 1 个子任务（内容和父任务一样） | **不拆** — 禁止创建单子任务包装壳 |
| 轻量任务 | 纯文档（<500行）、单脚本（<200行）、配置修改、typo 修复 | **不拆** — 零分解价值 |

**如果不拆**：在父 issue 上添加 `stage:split-done` label 并评论「无需拆分 — 单任务直接进入开发」，不创建任何子 issue。

**常见错误（此检查要拦住的）**：
- 一个 README.md 拆成「研究→设计→编写→审查」四个子任务 — 复杂度+轻量任务双重驳回
- 创建一个和父任务内容完全一样的子任务 — 1:1 映射驳回

## 拆分原则

### 粒度标准
- 一个 Task 应该在一个开发周期内完成（1-3 天）
- 一个 Task 只做一件事，职责单一
- 如果 Task 需要同时改动 FE 和 BE，拆成两个子 Task

### DAG 依赖图（仅在通过必要性检查、确认需要拆分后执行）

拆分前先分析任务依赖关系，画出有向无环图：

1. 找出所有任务及其类型（FE/BE）
2. 标注依赖：B 依赖 A 表示 A 必须先完成，B 才能开始
3. 识别根任务（无依赖）—— 这些会被 Autopilot 立即送入 Squad
4. 识别依赖任务 —— 等待前置任务 done 后由 Autopilot 自动解封

**示例 DAG：**
```
TSI-301 (BE: HTTP Client)       <- 根任务，依赖=无 → Autopilot 立即送入 Squad
    |
    v
TSI-302 (BE: Adapter Poll)      <- 依赖 TSI-301 → 等待 TSI-301 done
    |
    v
TSI-303 (BE: Engine Core)       <- 依赖 TSI-302 → 等待 TSI-302 done
```

> **注意**：PM 只负责创建任务和标注依赖。任务的激活和分配由 Autopilot 定时扫描 `依赖:` 字段自动完成，PM 不手动 assign。

### 拆分步骤
1. 阅读 Epic 的目标和范围
2. 列出所有需要交付的功能点
3. 每个功能点拆成独立 Task
4. 标注依赖关系（A 必须先于 B）

## 验收标准写法

每条验收标准必须满足：**可观测、可验证、无歧义**。

### 好的验收标准
```
- 用户输入邮箱和密码后点击"登录"，3 秒内跳转到首页
- 密码错误时页面显示红色提示"密码错误，还剩 N 次尝试"
- 连续 5 次失败后账号锁定，提示"账号已锁定，请 15 分钟后重试"
```

### 差的验收标准
```
- 登录功能正常  ← 什么叫正常？
- 用户体验好    ← 怎么验证？
- 自己测一下    ← 测什么？
```

## 全栈任务拆分

当功能同时涉及前端和后端时：

1. 先创建后端 Task，定义 API 契约（路径、参数、返回值）
2. 再创建前端 Task，描述中引用后端 Task 的 API 契约
3. 后端 Task 描述模板：
```
父 issue: <Epic ID>
依赖: 无

## API 契约
- POST /api/login
- 请求: {email, password}
- 响应: {token, user} 或 {error, message, remaining_attempts}
- 错误码: 401 密码错误, 423 账号锁定

## 验收标准
- 正确密码返回 token 和用户信息
- 错误密码返回 401 和剩余尝试次数
- 第 5 次失败返回 423
```

4. 前端 Task 描述模板：
```
父 issue: <Epic ID>
依赖: <后端 Task ID>

## 验收标准
- 输入邮箱密码点击登录，成功后跳转首页
- 密码错误显示 API 返回的错误信息
- 锁定状态显示倒计时
```

## Task 描述模板

```
父 issue: <Epic 或父 Task ID>
依赖: <前置Task ID 或 无>

## 背景
<一句话描述为什么需要这个功能>

## 验收标准
- <标准 1>
- <标准 2>
- <标准 3>

## 约束（可选）
- <技术约束或限制>
```

# 任务拆分与验收标准指南

## ⚠️ 拆分必要性检查（最优先）

任务拆分不是机械操作。**拆之前先判断是否需要拆。**

| 检查项 | 条件 | 结论 |
|--------|------|------|
| 复杂度 | 需要 >1 人或 >4 小时专注工作 | 可以拆 |
| 复杂度 | 一个人 ≤4 小时能完成 | **不拆** |
| 独立性 | ≥2 个真正独立、有各自验收标准的交付物 | 可以拆 |
| 1:1 映射 | 拆分后只有 1 个子任务（内容和父任务一样） | **不拆** |
| 轻量任务 | 纯文档、单脚本（<200行）、配置修改、typo 修复 | **不拆** |

**如果不拆**：评论「无需拆分 — 单任务直接进入开发。流程已更新。」

## 拆分原则

### 粒度标准
- 一个 Task 应该在一个开发周期内完成（1-3 天）
- 一个 Task 只做一件事，职责单一
- 如果 Task 需要同时改动 FE 和 BE，拆成两个子 Task

### DAG 依赖图

拆分前先分析任务依赖关系，画出有向无环图：
1. 找出所有任务及其类型（FE/BE）
2. 标注依赖：B 依赖 A 表示 A 必须先完成，B 才能开始
3. 识别根任务（无依赖）—— Lynx 立即委派
4. 识别依赖任务 —— 等待前置 TSI done 后 Lynx 自动推进

**创建子 issue 后，如有依赖，用 `前置依赖` text property 标注：**
```bash
multica issue property set "$CHILD_ID" --name "前置依赖" --value "TSI-301, TSI-302"
```

**示例 DAG：**
```
TSI-301 (BE: HTTP Client)       ← 根任务，前置依赖=空 → Lynx 立即委派
    |
    v
TSI-302 (BE: Adapter Poll)      ← 前置依赖: TSI-301 → 等待 TSI-301 done
    |
    v
TSI-303 (BE: Engine Core)       ← 前置依赖: TSI-302 → 等待 TSI-302 done
```

> PM 只负责创建任务和标注依赖。任务推进由 Lynx 读 `前置依赖` property 自动完成。

### Property 类型选择 🚨 必须执行

**每个子 issue 必须设置一个 Property 类型，状态为「起始」。**

```bash
multica issue property set "$CHILD_ID" --name "<Property>" --value "起始"
```

| 子任务类型 | Property |
|-----------|----------|
| Feature 开发 | 开发单 |
| Bug fix | Bug单 |
| Refactor | 开发单 |
| Trivial / Doc | Bug单 |
| 验收测试 | 验收单 |

> 「起始」标识 issue 类型，不推进阶段。Leader 跳过「起始」，从第一个实际阶段开始委派。

## 验收标准写法

每条验收标准必须满足：**可观测、可验证、无歧义**。

### 好的验收标准
```
- 用户输入邮箱和密码后点击"登录"，3 秒内跳转到首页
- 密码错误时页面显示红色提示"密码错误，还剩 N 次尝试"
- 连续 5 次失败后账号锁定，提示"账号已锁定，请 15 分钟后重试"
```

### 差的验收标准
```
- 登录功能正常  ← 什么叫正常？
- 用户体验好    ← 怎么验证？
```

## 全栈任务拆分

当功能同时涉及前端和后端时：
1. 先创建后端 Task，定义 API 契约
2. 再创建前端 Task，描述中引用后端 Task 的 TSI
3. 前端 Task 设 `前置依赖` property 指向后端 TSI

### 后端 Task 描述模板
```
## API 契约
- POST /api/login
- 请求: {email, password}
- 响应: {token, user} 或 {error, message, remaining_attempts}
- 错误码: 401 密码错误, 423 账号锁定

## 验收标准
- 正确密码返回 token 和用户信息
- 错误密码返回 401 和剩余尝试次数
- 第 5 次失败返回 423
```

### 前端 Task 描述模板
```
## 验收标准
- 输入邮箱密码点击登录，成功后跳转首页
- 密码错误显示 API 返回的错误信息
- 锁定状态显示倒计时
```

## Task 描述模板

```
## 背景
<一句话描述为什么需要这个功能>

## 验收标准
- <标准 1>
- <标准 2>
- <标准 3>

## 约束（可选）
- <技术约束或限制>
```

> 依赖关系通过 `前置依赖` property 标注，不写入 description。

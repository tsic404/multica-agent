# QA Testing Workflow

本技能定义通用 QA 验收测试流程。项目级 `<project>-qa-testing` 提供测试场景，本技能提供执行方法论。

## 执行流程

### 1. 加载项目 Skill

```bash
read_file .agent_context/skills/<project>-qa-testing/SKILL.md
```

如果项目 skill 不存在 → **QA_BLOCKED**（原因：`qa-testing skill not found`）。

### 2. 构建 + 启动

按项目 skill 的「前提条件」执行：构建 → 启动测试环境 → 准备测试数据。

构建失败 → **QA_BLOCKED**。

### 3. 执行场景

遍历项目 skill 中的所有场景。每个场景：

1. 执行命令
2. 记录：退出码 + 实际输出 + 验证方法
3. 对照场景的 ✅ PASS 条件判定通过/失败

路线选择：

| 项目类型 | 路线 | 方法 |
|---------|------|------|
| CLI/后端 | 用户模拟 | 以真实用户身份操作，凭直觉发现 bug |
| Web UI | 浏览器自动化 | 按项目 skill 场景操作，截图 + vision 分析 |
| 数据/模型 | 验收标准对照 | 逐条对照 issue 验收标准验证 |

### 4. 证据收集

每个场景的输出格式：

```
| # | 场景 | 命令 | 退出码 | 结果 |
|---|------|------|:------:|------|
| N | <场景名> | <命令> | <code> | <单行 ≤80 字> |
```

通过的行附可验证证据（终端输出/截图/文件校验），失败的行标注失败原因。

---

## 完成协议

### 裁决

只发 **一条** 评论，包含裁决 + 证据表：

```
**QA_PASSED** 或 **QA_FAILED** 或 **QA_BLOCKED**

Commit: `$COMMIT`
Branch: `$REMOTE_BRANCH`

| # | 场景 | 命令 | 退出码 | 结果 |
|---|------|------|:------:|------|
| ... | ... | ... | ... | ... |
```

---

## 超出范围缺口

QA_FAILED 时，在评论中加 `## 超出范围缺口` 表格：

| # | 问题描述 | 类型 | 建议 |
|---|------|------|------|
| 1 | <具体问题> | bug/feature | <修复建议> |

**不创建 fix issue** — Squad Leader 处理。

---

## 常见陷阱

### 1. 只执行验收标准，不走用户旅程

项目 skill 要求「用户模拟」时，必须至少走 2 个完整用户旅程。不能只对 checklist 打勾。

### 2. 工具不可用仍虚构结果

`agent-browser` 不在 PATH、`ffprobe` 命令不存在 → 标注为 **QA_BLOCKED**（原因：`tool unavailable`），不要编造测试结果。

### 3. 提前停止不发票决

**完成协议 = 发布裁决**。描述进度不等于完成。没发票决 = 任务失败。

### 4. 修 bug 而非报告 bug

**只测试，不修代码。** 发现的问题列在「超出范围缺口」，不要自己改代码。

### 5. 项目 skill 加载失败静默跳过

项目 skill 不存在 → 立即 **QA_BLOCKED**，不要凭常识猜测测试内容。

---

## 裁决定义

| 裁决 | 条件 |
|------|------|
| **QA_PASSED** | 项目 skill 中 P0 + P1 全部通过 |
| **QA_FAILED** | 任何 P0 或 P1 失败 |
| **QA_BLOCKED** | 构建失败 / 环境无法启动 / 项目 skill 缺失 / 必需工具不可用 |

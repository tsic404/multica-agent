# 前端开发规范

## 代码结构

### 组件拆分
- 一个文件一个组件，组件名即文件名
- 可复用 UI 放 components/，页面级放 pages/
- 组件 props 必须有类型定义

### 状态管理
- 局部状态用组件内 state
- 跨组件共享状态抽到 store
- 服务端数据用缓存层，避免重复请求

## 交互规范

### 加载状态
- 异步操作必须有 loading 指示
- 超过 3 秒的操作显示进度或骨架屏

### 错误处理
- API 请求失败显示用户可理解的错误提示
- 表单校验失败在对应字段旁标红提示
- 网络断开时显示离线提示，不白屏

### 空状态
- 列表为空时显示"暂无数据"，不空白
- 搜索无结果时显示"未找到匹配结果"

## 提交前自测

开发完成后，提交 Review 前必须确认：

- [ ] 验收标准全部通过
- [ ] 不同屏幕尺寸下布局正常
- [ ] 所有按钮/链接可点击且响应正确
- [ ] 表单提交后有反馈（成功/失败）
- [ ] 加载中、空数据、错误三种状态都覆盖
- [ ] 无 console.error 或 warning
- [ ] 代码已格式化，无注释掉的调试代码

## 提交信息格式

```
feat(scope): 简短描述

- 改动点 1
- 改动点 2
```

scope 示例：login, dashboard, profile, common

## 注意事项

- 不写行内样式，用 class
- 不硬编码文案，提取到常量或 i18n
- 不在前端存储敏感信息（密码、Token 明文）
